# Ticket Writing Checklist

## Before the review gate
- [ ] Project resolved via `project-resolving`; envelope kept
- [ ] Issue type stated or asked
- [ ] Title starts with a resolved component or partner name
- [ ] Title length and verb rule match the type
- [ ] Description is one paragraph: situation, change, why — no implementation
- [ ] Criteria present only if the type takes them; 3–7, pass/fail, weighted
- [ ] Open questions only if real
- [ ] Duplicate search run; hits shown in the gate

## Before create
- [ ] Full draft approved explicitly, after the last revision
- [ ] `create_call` filled with summary, description, parent only
- [ ] No resolved value overridden
- [ ] Created issue read back; envelope notes printed with the result
