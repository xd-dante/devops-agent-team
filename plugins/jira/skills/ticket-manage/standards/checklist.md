# Ticket Checklist

## Reading
- [ ] Key parsed and confirmed
- [ ] Summary, description **and the acceptance-criteria field** read
- [ ] **Every attachment fetched and read** — never work from the title
- [ ] Comment thread read to the end (the plan often changed there)
- [ ] Linked issues checked for dependencies and duplicates
- [ ] Environment taken from the ticket, not assumed
- [ ] Affected repos identified before implementation starts

## Creating
- [ ] Duplicate search run first
- [ ] Title 2–5 words, no leading verb
- [ ] Description states what and why, not the implementation plan
- [ ] Acceptance criteria in their own field
- [ ] Field ids discovered, not hardcoded
- [ ] Assignee resolved via lookup, never guessed
- [ ] One ticket per independently actionable item

## Updating
- [ ] Comment states conclusion first, then evidence
- [ ] Every PR referenced by URL
- [ ] Transition target read from the available transitions, not guessed
- [ ] "Not doing this" carries its reasoning in a comment first

## Reporting
- [ ] Ticket key and URL given
- [ ] Scope restated in your own words for confirmation
- [ ] Ambiguities named explicitly — nothing invented to fill a gap
