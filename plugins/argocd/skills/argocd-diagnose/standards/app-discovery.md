# Application Discovery

## Find the app and its owner

```bash
kubectl get applications -A
kubectl get application -n <ns> <app> -o yaml
argocd app get <app>
```

Applications are usually **not** created by hand — they are generated by
infrastructure-as-code. Find the owning repo before proposing a change to the
Application itself:

```bash
grep -rln "<app-name>" <infra-repo>/ 2>/dev/null
```

An app that looks unmanaged usually is not. Check every infrastructure repo
in `.devops-agents.yml` `repos` before saying so.

## Fields that matter, and who sets them

| Field | Typically set by | Note |
|-------|------------------|------|
| `source.repoURL` / `path` | infrastructure code | |
| `source.targetRevision` | infrastructure code | **May be pinned** — see `actions/revision-pin.md` |
| `source.helm.valueFiles` | infrastructure code | Static chart values arrive this way and **bypass** any value shaping in the module |
| `source.helm.valuesObject` / `parameters` | infrastructure code | Computed values only — secret references, identity bindings, generated hostnames |
| `syncPolicy.automated` | infrastructure code | Frequently **off**, making syncs deliberate |
| `metadata.annotations` | infrastructure code | Includes integration annotations for promotion tooling |

## Automated sync may be off

Check before diagnosing anything:

```bash
kubectl get application -n <ns> <app> -o jsonpath='{.spec.syncPolicy}{"\n"}'
```

If it is off, the consequences that catch people out:

- merging a chart PR deploys **nothing** until someone syncs
- after merging a change to a platform chart, its Application must be synced
  or the new manifests never land
- promotion tooling that forces its own sync still works — it mutates the
  Application's operation field directly, independent of this setting

## Two value paths

| Kind | Lives in | Involves value shaping? |
|------|----------|-------------------------|
| **Static** — probes, ports, env, replicas, resources, image tag | chart values files, via `valueFiles` | No — bypassed |
| **Computed** — secret references, identity bindings, generated names | infrastructure module → `valuesObject` | Yes |

Classify before diagnosing "the value is not taking effect". Half of those
reports are a value set on the wrong path.
